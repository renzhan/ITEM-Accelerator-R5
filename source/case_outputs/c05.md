#### D1.2.5 General：Record & Reply｜20 分钟

> 本节介绍 ItemGPT Record & Reply 的理念和实现方式，配一段真实系统的演示视频；现场演示视时间而定。

##### D1.2.5.1 为什么：做得出来、说不清楚

很多物流运营流程，业务人员每天都在做，却很难写清楚：要在多个网页系统和桌面软件之间来回切换，还有大量靠经验的判断。Record & Reply 让业务人员演示一遍，ItemGPT 就把流程学成可复用的技能，并整理成给人看的 SOP。适合业务人员难以描述、但能直接演示的流程，例如 backlog 处理、物流数据采集、线下资料整理和跨系统操作。

| 痛点 | 我们的做法 |
|---|---|
| 写 SOP 门槛高：专家要占用处理业务的时间去写，写出来也常漏掉页面切换、例外和手工步骤 | 业务人员照常操作一遍，ItemGPT 记录下来并整理成 SOP |
| 隐性经验说不清：靠访谈和事后回忆，判断依据容易遗漏 | 从真实操作中提取判断，标出不确定的地方，交给专家确认 |
| 写好了 SOP，仍要人照着做：查单、截图、回复客户这类跨系统操作每天重复 | 学成技能后，一句话交给 ItemGPT 去做 |
| 想自动化就得等开发：网页系统、Excel、邮件客户端和老系统客户端往往没有现成接口 | 浏览器扩展操作网页，桌面端 ItemGPT Companion 操作本机应用和文件，不需要先做接口开发 |
| SOP 容易过时：流程变了，没人更新文档 | 再演示一遍，或在对话里改一句，技能和 SOP 一起更新 |

**演示视频（FMS 客服工单）。** 客户在工单里询问提货进度；客服到 FMS 按单号查订单和行程，打开 Trip ETA 地图截图，再回到工单附图回复。视频依次展示录制、学习、新对话回放、一句话生成 SOP 和数据留存。真实系统录屏，个人信息与网址已脱敏，部分等待已快进；约 6 分钟，中文配音和字幕。观看链接（YouTube）：<https://youtu.be/5mhN76BEO8M>

##### D1.2.5.2 怎么实现（一）：采集与理解

1. **用户发起。** 在 ItemGPT 对话里说明要演示的任务，对话中出现录制卡片，用户点开始。录制只发生在用户主动开始和结束之间。
2. **三种录制方式。**
   - 浏览器：浏览器扩展录制标签页画面，同时记录点击、输入、页面跳转等操作时间线。
   - 桌面：桌面端 ItemGPT Companion 录制屏幕，同时记录桌面应用里的点击、切换应用等操作。
   - 混合：两者同时进行，适合在网页和桌面软件之间来回切换的流程。
3. **完成后上传。** 用户点完成，录像和操作时间线上传到当前对话。
4. **理解流程。** ItemGPT 逐段查看时间线和视频：以操作时间线为准，视频补充画面信息；区分演示中的具体值（单号、收件人、文件名）和可以复用的步骤，回放时不照搬旧值。
5. **标出不确定的地方，不靠猜。** 例如 FMS 案例里，ItemGPT 指出演示时提交的是内部备注而不是给客户的回复，视频里还录进了一个无关窗口；这些都写进技能，作为回放时的注意事项。

##### D1.2.5.3 怎么实现（二）：沉淀与执行

**两份产出。**
- 技能：给 Agent 执行。默认只有本人可用；确认好用后，可以发布给同一租户的同事。
- SOP：在学习时的对话里发一句话即可生成，包含适用场景、需要的系统和权限、每一步在哪个系统做什么和怎么判断、异常处理，以及录制中发现的待确认事项。

**回放执行。**
- 新开对话，用自然语言提出需求；ItemGPT 加载技能，读取当前页面再操作，不是机械重复鼠标点击。例如 WMS 装车照片任务，换一个新的 Load No 也能完成。
- 网页里的步骤由浏览器扩展执行；桌面应用和本地文件由 Companion 执行；两边可以交接，例如照片从 WMS 存到本地，再作为附件加进 Mail。FMS 案例中，网页里做不了的粘贴截图也由 Companion 在桌面完成。
- 沿用用户自己浏览器里的登录状态，不需要重新登录。

**核验与更新。**
- 完成后核验结果，例如邮件发出后到"已发送"中核对收件人、主题和附件，不把窗口关闭当作成功。
- 再演示同一个流程时，ItemGPT 更新原来的技能，而不是新建一份。

##### D1.2.5.4 人工确认、接管与合规

**什么时候交给人。**
- 需要登录、会话过期、验证码或多因素认证时，ItemGPT 不代填账号密码，请用户在自己的浏览器里完成后再继续。
- 用户只要求查找或起草时，只存草稿，不擅自发送；缺少信息或无法唯一定位（例如一个单号查到多条）时，先问人。

**合规。**
- 录制由用户发起和结束。
- 画面中的个人信息和网址在对外分享前需要脱敏；本节视频已脱敏。
- 原始视频和操作元数据默认 1 天后删除，保留期可按业务需求设定；长期保留的是结构化的技能和 SOP。
- 写入、发送、提交等动作按用户授权执行，每一步都留在对话记录里，便于事后核查。

**为什么在用户自己的电脑上运行。**

| | 用户自己的电脑（浏览器扩展＋桌面端） | 云端托管的无头浏览器 |
|---|---|---|
| 登录 | 沿用已有登录状态 | 每个系统都要重新登录，会话过期还要再登 |
| 凭证 | 账号密码不交给 ItemGPT | 要把账号密码交给云端保存 |
| 内网与白名单 | 内网、VPN、IP 白名单照常可用 | 常被多因素认证、验证码、IP 白名单拦住 |
| 本机应用 | 可操作任意桌面应用和本地文件；读不到界面控件时，按屏幕画面操作 | 接触不到本机应用和文件 |
| 权限与可见 | 与本人权限一致，每一步都在眼前，随时可以停下 | 要另开服务账号，在后台运行，看不到过程 |

##### D1.2.5.5 变更与复用

**规则变了怎么办。** 再演示一遍，或者在对话里直接说明新规则，例如"封条照片看不清就先问我，不要发"。ItemGPT 更新原来的技能，保留没有被新规则推翻的内容。

**复用与共享。**
- 技能可以发布给同一租户的同事。同事使用时，在自己的浏览器里、用自己的登录和权限执行，不共用账号。
- 技能更新后，所有使用它的同事都会用到新版本，因此发布前建议由业务 Owner 审阅对应的 SOP。
- SOP 可以直接用于培训和交接；录制、学习、回放这套方法可以用到其他跨系统流程。

**需要重新确认的。** 换到新系统或新场景时，账号权限、页面结构和业务规则都要重新演示或确认，不能因为录得下来就假设可以直接照搬。

##### D1.2.5.6 现场演示（可选）与讨论

**现场演示（视时间而定）。**
- 场景：客户提供 Load No，要这票货的装车和封条照片。
- 演示：在浏览器里用 WMS 按 Load No 找到 Load 和关联的 Load Task，打开 Photos；再在桌面上用 Mail 把照片发出。
- 回放：新开对话，换一个 Load No，一句话让 ItemGPT 完成，并到"已发送"中核对结果。
- 可选：在对话里改一条规则后重跑，展示技能如何更新。
- 时长参考：录制约 2 分钟，学习约 5–7 分钟，回放约 3 分钟。
