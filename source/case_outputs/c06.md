# D1.2.6 ISS CEC 流程分析＋Genesys 集成｜20 分钟

> 本扩写只基于输入案例与作者契约。新增设计均标为“建议”；未知运营数据、接口范围、责任人和结果列入“待补证据”，不视为已实现。

## D1.2.6.1 业务结果、改造前流程与预录视频｜建议

### 业务痛点与期望结果

- **已知痛点：**业务不能只依赖 IT 判断哪些流程值得自动化；实际坐席可能跨知识库、订单、服务和沟通系统操作，并包含隐性判断与未文档化步骤。
- **建议期望结果：**通过经授权的真实工作视频/录屏形成可审核的 CEC SOP，识别一个高频查询、重复切换、标准回复、信息补充或升级步骤，并明确其属于“可以自动、需要辅助、必须由人决定”中的哪一类。
- **建议验收：**现场能够从一段脱敏或模拟录屏追溯到 SOP 步骤、知识/语义承载位置、允许的 Connector/Tools、人工接管点、调用日志和状态回写点；不把“有无头化”解释为取消坐席。

### 改造前流程（待现场确认）

1. 坐席接收客户请求并在多个知识库、订单、服务和沟通系统间切换。
2. 坐席依赖未文档化经验进行查询、判断、补充信息、回复或升级。
3. 业务专家或 IT 事后判断哪些步骤可能自动化，但现有分母、频次、错误和耗时基线尚未提供。
4. 录屏范围、电话内容、个人信息、授权、接口、日志与留存边界仍需按 D1.2.5 的审核边界确认。

### 预录视频设计（建议）

- `video-slot` 使用 `data-case-id=c06`，默认不放 `src`。预录内容应展示：一个具体坐席任务、跨系统切换、判断分支、标准回复/信息补充、升级点和最终状态。
- 视频应区分**真实、脱敏、模拟**：真实材料须有授权；脱敏材料需说明删改字段；模拟材料需标出与实际接口、权限、规则的差异。
- **待补证据：**第一批观察任务、录屏授权与留存期限、电话/个人信息范围、可展示的接口及结果回写证据。

## D1.2.6.2 改造后闭环：正常任务、异常与人工接管｜建议

### 建议闭环

1. **输入与识别：**接收经授权的坐席工作上下文，识别任务类型、必要字段与相关知识。
2. **正常任务：**在 SOP、UKM、Ontology 或 Skill 中检索；通过已审核的 Connector/Tools 查询或生成建议；允许的标准后台动作按权限执行。
3. **缺失信息：**提示缺失字段，向坐席请求补充；未满足前不执行需要完整信息的动作。
4. **异常与高风险：**规则冲突、接口失败、敏感沟通、例外处理或高风险动作转人工；坐席可接管并修正建议。
5. **状态回写：**记录调用、权限结果、人工接管、修正与最终处理结果；在真实范围确认后回写知识和业务状态。
6. **最终业务结果：**以业务系统中可核验的最终状态作为验收对象；当前没有已证实的成功率、节省时间或自动执行结果，不应提前填写。

### 边界

- 自动化辅助坐席，而不是取消坐席；敏感沟通、例外处理和高风险动作保留人的责任。
- **待补证据：**允许执行的首个动作、Genesys 相关接口/Connector/Tools、权限模型、失败码、人工接管日志、状态回写字段及留存方式。

## D1.2.6.3 实施过程、困难、采用与持续改进｜建议

### 输入与建设过程

1. 由 ISS Biz（team）与坐席选择一个可授权、可脱敏、可复盘的高频任务。
2. Tom 主持；ITEM 直接对接 COO AI Team/Hollis 紧密共同开发并依托现有成果扩展；DT 按需支撑数据、代码、软件、接口及跨部门事项。
3. 对录屏逐段标注任务、字段、判断、系统切换、例外、权限、输出和人工接管点。
4. 业务专家与坐席审核 SOP；将经审核内容放入 UKM、Ontology 或 Skill；按实际范围连接接口并设计日志与回写。
5. 用小范围任务做回归；依据人工修正、异常与最终处理结果更新知识、路由和规则。

### 可能困难与建议机制

- **可能困难：**授权或个人信息限制导致录屏不可用；建议先使用脱敏/模拟材料，并保留与真实流程的差异清单。
- **可能困难：**隐性判断无法直接转成规则；建议把“可自动/需辅助/必须人工”作为审核表，而不是强行产品化。
- **可能困难：**接口权限、字段语义、日志和回写边界不清；建议先画最小闭环，逐项由 ISS Biz、DT 和接口 Owner 确认。
- **可能困难：**建议回复与实际业务结果不一致；建议设置人工接管、回归样本、错误级别和回滚门槛。

### 推动采用与持续改进

先让坐席看到建议、来源、缺失字段和接管点，再决定是否开放受控执行；每轮只扩大已验证的任务范围。运营机制建议包括样本抽检、知识版本、接口变更评审、权限复核、调用/接管/修正日志与定期回归。以上均为建议，实际采用率和效果待测。

## D1.2.6.6 思考：业务变更链与可沉淀资产｜建议

### 业务变更链

**业务提出规则 → 专家审核 → FDE 修改 → 回归验证 → 发布或回滚。**

每次变更建议绑定：规则版本、来源任务、适用范围、审批人、回归样本、错误级别、发布窗口、回滚条件和责任人。Genesys 相关动作的权限或字段变更也应走同一链路，而不是直接改线上行为。

### 可沉淀到核心知识库的内容

- 授权范围、脱敏规则、审核记录与可追溯来源。
- CEC SOP、任务分类、例外/升级规则、人工责任边界。
- UKM / Ontology 术语映射、Skill 输入输出契约和 Connector/Tools 权限。
- 回归样本、评测口径、错误分级、接管与修正标签。
- 运营机制：版本、抽检、失效、权限复核、日志留存、回滚和停止条件。

### 第二场景复用边界

可复用：观察标注表、授权清单模板、任务分类、审核链、日志字段、回归和回滚机制。需重验证：领域术语、知识来源、接口字段、权限、敏感沟通规则、风险等级、业务结果定义和坐席接管点。不可把第一场景的接口成功或质量结果直接迁移。

## D1.2.6.7 可重复交付与现场动手｜建议

### 可重复方法

1. **场景资格：**确认授权、可脱敏、任务边界、业务Owner和停止条件。
2. **被动观察：**录屏/视频转成步骤、判断、系统、字段、例外和输出标注。
3. **能力分级：**把步骤分为自动、辅助、人工；注明依据和风险。
4. **知识与动作：**将审核内容放入 UKM / Ontology / Skill，配置最小权限 Connector/Tools。
5. **闭环验收：**以正常、缺失、异常、接管、回写和最终结果做回归。
6. **运营交付：**移交Owner、版本、日志、抽检、评测、维护、回滚和停止机制。

### 通用核心与场景配置

- **通用核心：**授权、观察标注、审核、任务分级、日志、回归、发布/回滚和责任矩阵。
- **场景配置：**CEC术语、知识来源、Genesys队列/动作、字段、权限、回复模板和升级规则。
- **接口与评测：**每个动作需记录输入、权限、响应、失败和回写；评测不只看模型输出，还看业务最终状态与人工接管。
- **维护：**知识失效、接口变更、规则更新和样本漂移触发复核；不满足质量/安全门槛时缩小范围、停止或转交人工。

### 现场动手产出（建议）

现场选一条规则或流程，完成一次小范围修改，产出：一页流程草稿或能力卡、输入/输出、允许/禁止动作、人工接管点、2–3条回归样本、验收口径、责任人和回滚/停止条件。若证据不足，产出“缩小范围/暂停/转交”决定，不强行产品化。

## D1.2.6.8 既有详细实践与边界补充

##### 验证点：全方位录屏，形成可审核的被动知识收集

与 D1.2.5 的区别在于：这里聚焦 CEC 的实际坐席流程，进一步验证如何把知识与动作接到 Genesys 及相关业务系统，而不是再重复一次通用视频生成 SOP。

##### 痛点

业务不能只依赖 IT 来判断哪些流程值得自动化。实际坐席可能要跨知识库、订单、服务和沟通系统操作，其中包含大量隐性判断和未文档化步骤。

##### 解决路径

**经授权视频/录屏 → CEC SOP → Agent → Genesys 集成与受控执行。**

1. 从真实工作过程识别高频查询、重复切换、标准回复、信息补充与升级步骤。
2. 由业务专家和坐席共同确认“可以自动、需要辅助、必须由人决定”的任务分类。
3. 经审核的 SOP 进入 UKM、Ontology 或 Skill；已有 UKM / EKP / EKF 接口按实际范围接入。
4. 用标准 Connector/Tools 将查询、建议、回复和允许的任务接到 Genesys 相关流程。
5. 记录调用、人工接管、最终处理结果与修正，回写知识和业务状态。

##### 演示与边界

展示从观察真实流程到识别一个自动化步骤，再到坐席调用或后台执行的闭环。无头化不等于取消坐席：标准后台任务可自动运行，敏感沟通、例外处理和高风险动作保留人的责任。

录屏范围、电话内容、个人信息、录音/录屏授权、接口、日志及原材料留存遵循 D1.2.5 的边界，不能因“被动采集”绕过审核。

##### 持续优化：自有模型

在任务范围稳定、授权数据充分、通用方案存在明确质量或成本缺口时，评估 CEC 自有或专域模型。先比较知识检索、规则、Prompt、路由、现有小模型或适配方案，再决定是否训练和长期维护模型。

旧稿中的 eSVC 小模型可作为相关分类/意图/路由能力候选；情绪识别等具体目标仍需确认。本节不将自有模型描述为已完成或必需前提。

经内部验证后，可继续讨论 CSAS Genesys AI App、标准产品及 Genesys Marketplace 推广；其成熟度、产品责任、数据/IP 及外部发布条件在实施计划中确认。

**本节结论：**第一批观察哪些坐席任务？哪个接口和动作可演示？自有模型要解决什么已被证明的缺口？
