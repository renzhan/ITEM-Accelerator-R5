怎么实现（二）：沉淀与执行How It Works (2): Learn and Run

一次演示得到两份产出：给 Agent 执行的技能和给人看的 SOP；回放时读当前页面再操作，不是机械重放。One demonstration yields two outputs: a skill the agent runs and an SOP people read. Replays read the current page instead of repeating clicks.

两份产出Two outputs

  • 技能：给 Agent 执行；默认仅本人可用，确认好用后可发布给同一租户的同事。Skill: run by the agent; private by default, and can be published to colleagues in the same tenant.
  • SOP：一句话生成，格式由 SOP 规范技能统一约定。SOP: generated from one sentence, in the format set by an SOP standard skill.
  • UNIS 用 SOP 管理站点统一管理生成的 SOP：sop.item.pubUNIS manages the generated SOPs on its SOP site: sop.item.pub

回放执行Replay

  • 新对话里用自然语言提需求，换新数据也能做，例如新的 Load No。Ask in plain language in a new chat; new inputs work, such as a new Load No.
  • 网页步骤由扩展执行，桌面应用和本地文件由 Companion 执行，两边可以交接。The extension runs web steps; Companion runs desktop apps and local files, and they hand work to each other.
  • 沿用用户自己的登录状态。It reuses the user's existing sign-ins.

核验与更新Verify and update

  • 完成后核验结果，例如邮件发出后到“已发送”核对收件人、主题和附件。It checks the result, for example recipient, subject and attachments in Sent mail.
  • 再演示同一个流程，会更新原来的技能，而不是新建一份。Demonstrating the same flow again updates the existing skill instead of adding a copy.
讨论Discussion一次执行要核验到什么程度，才算真正完成？What evidence shows that a run is really complete?
