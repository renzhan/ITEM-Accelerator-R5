怎么实现（一）：采集与理解How It Works (1): Capture and Understand

录制由用户在对话里发起和结束；ItemGPT 以操作时间线为准、视频为补充，弄清每一步在做什么。The user starts and finishes the recording from the chat; ItemGPT reads the action timeline first and the video second to understand each step.

三种录制方式Three capture modes

  • 浏览器：扩展录标签页画面，并记录点击、输入和页面跳转。Browser: the extension records the tab plus clicks, typing and navigation.
  • 桌面：Companion 录屏幕，并记录桌面应用里的操作。Desktop: Companion records the screen plus actions in desktop apps.
  • 混合：两者同时，适合在网页和桌面软件之间来回切换的流程。Mixed: both at once, for flows that move between web and desktop apps.

理解流程Understand the flow

  • 以操作时间线为准，视频补充画面信息。The action timeline leads; the video fills in what was on screen.
  • 区分演示用的具体值（单号、收件人）和可复用的步骤，回放时不照搬旧值。Demo values such as order numbers and recipients are kept apart from reusable steps, so replays never reuse old values.

由用户发起和结束Started and finished by the user

在对话里说明要演示的任务 → 点开始 → 照常操作 → 点完成，录像和操作时间线上传到当前对话。Describe the task in chat → Start → work as usual → Finish; the video and the action timeline upload to the chat.

标出不确定，不靠猜Flag uncertainty instead of guessing

FMS 案例中，ItemGPT 指出演示时提交的是内部备注而不是客户回复，还录进了无关窗口；这些都写进技能，作为回放时的注意事项。In the FMS case, ItemGPT noticed that the demo posted an internal note rather than a customer reply, and that an unrelated window was recorded; both became cautions in the skill.
