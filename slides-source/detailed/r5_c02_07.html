可重复交付＋动手：小范围草稿也要可验收Repeatable delivery + hands-on: even a small draft needs acceptance

现场不追求强行产品化；要产出能力卡、映射、用例和责任，并保留失败时的缩小、停止与转交机制。The room need not force productisation; it should produce a capability card, mappings, tests and owners, with stop, narrow and handoff paths.

通用交付流程Repeatable flow

  • 授权/范围 → 代码/字段/权限/接口盘点Access/scope → code/field/access/interface inventory
  • 本地环境 → 页面生成 → 校验/错误/ActionLocal environment → page generation → validation/errors/Actions
  • 审核 → 功能/接口测试 → 发布、观测、维护或回滚Review → functional/interface tests → release, observe, maintain or roll back
CAPABILITY CARD场景、输入、输出、边界Scene, input, output, boundary
FIELD MAP字段、状态、权限、接口Fields, states, access, interfaces
ACCEPTANCE最小用例与责任Minimum tests and owners
FAILURE LOG失败、回滚、转交Failure, rollback, handoff

现场修改一个低风险规则Change one low-risk rule live

  • 建议：新增“异常类型”待审核选项，或将“处理建议”设为必填。Suggested: add a review-pending exception type or make recommendation required.
  • 若无真实代码/接口：用脱敏或模拟数据展示草稿，并标注未完成真实回写。If real code/interfaces are unavailable: use redacted or simulated data and mark write-back as uncompleted.
  • 失败时：只读/模拟、回到上一版本、转交 ISS Biz 与 DT/安全审核。On failure: read-only/simulate, revert to the prior version, or hand off to ISS Biz and DT/security.

待补：实际修改内容、参与人、测试结果、目标环境、维护 Owner。To add: actual change, participants, test result, target environment and maintenance Owner.
