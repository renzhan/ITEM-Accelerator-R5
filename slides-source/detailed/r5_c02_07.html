可重复交付＋动手：现场说一个改动，走完草稿到发布Repeatable delivery + hands-on: state one change live, take it from draft to release

不追求现场产品化：用一个低风险改动，检验对话修改、试运行、发布和回退是否完整，并保留停止与转交路径。No forced productisation: one low-risk change checks that chat revision, trial, release and rollback are complete, with stop and handoff paths.

通用交付流程Repeatable flow

  • 说出需求 → Agent 查本体与接口 → 确认计划卡或草稿State the need → Agent checks ontology and APIs → approve the plan card or draft
  • 生成 Task / Page / View → 用真实数据试运行 → 修改Generate Task / Page / View → trial on real data → revise
  • 有权限的人发布 → 导出定制包 → 生产导入为草稿、审批、发布Authorised publish → export package → import to production as draft, approve, publish

现场修改一个低风险规则Change one low-risk rule live

  • 对 Agent 说：“巡检上报加一个必选的破损原因”，或“放货前必须拍照”。Tell the Agent: “add a required damage reason to the patrol report”, or “require a photo before placing”.
  • 测试环境试运行后发布 v2；发布预览列出将跟随新版本的进行中任务。Trial in test, then publish v2; the preview lists in-progress tasks that will follow.
  • 失败时：留在草稿不发布；已发布可停用或从旧版本重新发布；接口缺失转 FDE/COO AI Team。On failure: stay in draft; deactivate or republish an older version; missing APIs go to FDE/COO AI Team.

待补：ISS 场景选择、参与人、试运行结果、目标环境与维护 Owner。To add: ISS scenario, participants, trial result, target environment and maintenance Owner.
