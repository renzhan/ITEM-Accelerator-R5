ISS 对标：要做到“现场说出来就能用”，ISS 还缺什么ISS benchmark: what ISS still lacks for “say it, use it”

前提有四个：Agent 懂 ISS 的业务和接口、能以本人权限调用、写入可追溯、发布受控。对标不是宣布 ISS 已具备，而是把缺口变成会中能回答的问题。Four prerequisites: the Agent knows ISS business and APIs, calls with the user's own access, writes are traceable, and release is controlled. Benchmarking does not claim ISS has them; it turns gaps into questions the room can answer.

会中直接提问并确认Ask and confirm in the room

  • Q1 哪个 ISS 现场需求像“巡检 → 集中处理 → 派工”，且能在测试环境验证？Which ISS floor need resembles patrol → triage → dispatch and can be validated in test?
  • Q2 哪些操作已有接口，哪些只能先做只读看板？Which operations already have APIs, and which can only start as read-only dashboards?
  • Q3 哪些动作必须人确认：发布、库存/货况调整、派工？Which actions need human confirmation: publish, stock or condition change, dispatch?
  • Q4 谁发布、谁审批定制包导入、谁授权回退旧版本？Who publishes, who approves package import, who authorises rollback?

每个问题当场记下 Owner、涉及的系统/环境和证据位置。For each question, record the Owner, system/environment and evidence location on the spot.

讨论Discussion如果 ISS 系统缺少可用接口或本体，是先做只读 View 看板，还是转交 DT 补接口？If ISS systems lack usable APIs or an ontology, start with a read-only View dashboard, or hand off to DT to add APIs?
