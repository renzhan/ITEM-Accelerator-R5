思考：业务规则变更，要留下可复用的证据链Reflection: business-rule change needs a reusable evidence chain

动态表单不是一次性生成物；真正可迁移的是授权、审核、回归、发布与维护的共同语言。A dynamic form is not a one-off artifact; the reusable asset is shared language for access, review, regression, release and maintenance.

01 · CHANGE CHAIN

业务变更链Change chain

  • 业务提规则Business proposes the rule
  • 专家审核→FDE 改Expert review → FDE changes
  • 回归→验收→发布/回滚Regression → acceptance → release/rollback

每一步保存版本、责任、证据和未决项。Keep version, owner, evidence and open items at every step.

02 · KNOWLEDGE

可沉淀资产Reusable assets

  • 字段/状态/权限、接口约定、Action 白名单Fields/states/access, interface conventions and Action allowlist
  • 错误与接管规则、脱敏要求、测试用例Error/takeover rules, redaction and test cases
  • 发布/回滚 SOP、失败样本、缺陷分级Release/rollback SOP, failures and defect severity
03 · REUSE

第二场景：复用与重验证Second scene: reuse and revalidate

  • 复用：需求模板、检查清单、版本/回滚框架。Reuse: need template, checklists and version/rollback frame.
  • 重验：对象语义、状态机、接口、权限、数据敏感性。Revalidate: object meaning, state machine, interfaces, access and sensitivity.
  • 首个页面通过，不推断所有 WMS 能力通过。One passing page does not prove all WMS capability.
