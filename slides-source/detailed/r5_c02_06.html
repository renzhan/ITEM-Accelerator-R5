思考：需求一直在变——改动走版本发布，积木越攒越多Reflection: needs keep changing—version every change, grow the blocks

动态表单不是一次性生成物：改一次就是一个新版本；能长期留下、带到下一个场景的，是本体、标准积木和受控发布机制。A dynamic form is not a one-off: every change is a new version, and what lasts and carries to the next scene is the ontology, the standard blocks and controlled release.

01 · CHANGE CHAIN

业务变更链Change chain

  • 现场提出修改 → Agent 改草稿 → 试运行验证Floor asks for a change → Agent edits the draft → trial run
  • 有权限的人发布新版本；进行中的任务保留已录结果，从新版本继续An authorised person publishes; in-progress tasks keep what is recorded and continue on the new version
  • 每个版本保留，可停用，也能从旧版本重新发布Every version is kept, can be deactivated or republished

生成成功不等于上线，发布始终是人的决定。Generated is not released; release is always a human decision.

02 · ASSETS

可沉淀资产Reusable assets

  • 懂业务：Item Ontology、接口目录、内部 SkillKnow-how: Item Ontology, API catalog, internal Skills
  • 标准步骤：Move Inventory 等，随系统持续扩充Standard steps: Move Inventory and more over time
  • 应用：任务类型、Dynamic Page、View、Custom Object 类型，可打包导入Apps: task types, Dynamic Pages, Views, Custom Object types, packaged for import
03 · REUSE

第二场景：复用与重验证Second scene: reuse and revalidate

  • 复用：Move Inventory 同样用于组装、补货、库位优化、坏货处理。Reuse: Move Inventory also serves assembly, replenishment, slotting and damage handling.
  • 重验：货况与上架映射、角色权限、客户数据语义、接口副作用。Revalidate: condition and putaway mapping, roles, customer data meaning, API side effects.
  • 一个任务类型通过，不推断所有场景通过。One passing task type does not prove every scenario.
