MD §D2.5.4 · Day 2

问题、证据与正式审批依赖，不带模糊结论进门Issues, Evidence and Formal Dependencies

把不确定性拆成可追踪的缺口：事实证据、责任 Owner、正式路径和下一步，不用“应该可以”替代确认。Turn uncertainty into traceable gaps: evidence, accountable Owner, formal path and next step; do not replace confirmation with “should work.”

依赖类别本轮需核对的证据缺口如何进入 D2.6
业务材料与验收真实输入、规则、样本、基线、指标、专家判定与排除项补证缩小；明确 Owner、截止日期与复审门
数据 / 代码 / 接口 / 环境来源、版本、接口、部署边界、日志、留存与回滚有条件继续；列出前置条件与验证结果
权限 / 安全 / 模型授权访问范围、敏感知识、模型许可、人工接管与风险控制暂缓转交或正式安全路径，不把建议写成批准
预算 / 资源 / 运维所需投入、容量、Training、告警、成本与退出责任会中确认投入；由对应 Owner 带入下一评审
EA / BIA / 生产变更架构、业务影响、采购、上线与生产审批入口记录正式审批/转交，不由会议共识代替
DependencyEvidence to checkHow it enters D2.6
Business and acceptanceReal inputs, rules, samples, baseline, metrics, expert judgment and exclusionsNarrow with evidence; name Owner and review gate
Data / code / interface / environmentSource, version, interfaces, deployment, logs, retention and rollbackConditional continuation with prerequisites
Access / security / model rightsScope, sensitive knowledge, model license, takeover and controlsDefer or transfer to formal Security path
Budget / resources / operationsInvestment, capacity, Training, alerts, cost and exit ownershipConfirm in meeting; carry to next review
EA / BIA / production changeArchitecture, impact, procurement, launch and production approval pathRecord formal approval or transfer
规则：缺证状态保留“待确认”；事实来源、版本、权限和证据链接随记录保存。Rule: keep missing evidence as “pending confirmation”; retain source, version, access and evidence links.
