实施过程：让 Agent 懂 WMS，只用标准积木搭应用Implementation: know WMS, build only from standard blocks

直接让 AI 写页面，常见的四个问题是：字段对不上、每个需求一张新表、绕过库存规则、生成即上线。做法是把这四件事都交给 WMS 已有的机制。AI-written pages fail four ways: wrong fields, a table per need, bypassed inventory rules, and shipping whatever is generated. We hand all four to existing WMS mechanisms.

01 · KNOW

懂业务Know the business

难点PROBLEM不懂 WMS 字段与接口，看着对、跑不通。Without WMS fields and APIs, it looks right but does not run.

做法APPROACHItem Ontology 描述对象、流程、规则与配置；按操作索引的接口目录和内部 Skill 告诉 Agent 该调哪个接口。目录里没有的操作不编造。Item Ontology describes objects, processes, rules and configuration; an operation-indexed API catalog and internal Skills tell the Agent which API to call. Nothing outside the catalog is invented.

02 · BLOCKS

用积木，不建表Blocks, not tables

难点PROBLEM每个需求建一张表，各自重写库存逻辑。Each need adds a table and rewrites inventory logic.

做法APPROACH通用三层存储（Context · Lines · Records）承载任务数据，无需建表；常用动作封装成标准步骤，如 Move Inventory 已含扫描、托管和库存流水。Shared three-layer storage (Context · Lines · Records) holds task data with no new tables; common actions become standard steps—Move Inventory already handles scanning, custody and stock transactions.

03 · READ

只读取数，本人权限Read-only, own access

难点PROBLEM页面直查多张表，越权或拖慢系统。Pages query many tables, overreach access or slow the system.

做法APPROACH页面数据由只读 View 汇总现有接口，在隔离沙箱中运行，只拿当前用户的只读令牌；起草前先用真实数据预览。Page data comes from a read-only View that combines existing APIs, runs in an isolated sandbox with only the user's read-only token, and is previewed on real data before drafting.

04 · RELEASE

先试后发Try, then release

难点PROBLEM生成即上线，出了错难回退。Generated means live, and mistakes are hard to undo.

做法APPROACH草稿 → 试运行 → 修改 → 保存为任务类型并发布；测试环境导出定制包，生产导入为草稿，审批后发布。Draft → trial → revise → save as a task type and publish; export a package from test, import to production as a draft, publish after approval.

以上机制已在 ITEM WMS 本地环境实现；在 ISS 系统中能否成立，需逐项验证。These mechanisms exist in the ITEM WMS local environment; each must be verified in ISS systems.

讨论DiscussionISS 现有系统能否提供业务本体和按操作索引的接口目录？缺少时先缩小为只读看板，还是转交 DT 补齐？Can ISS systems provide a business ontology and an operation-indexed API catalog? If not, narrow to read-only dashboards first, or hand off to DT?
