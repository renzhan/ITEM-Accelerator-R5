改造后闭环：正常任务、接管与状态回写After: normal task, takeover and state write-back

闭环的终点不是表单提交，而是有证据的业务状态变化；缺失信息和高风险 Action 必须停在人工确认门。The endpoint is not form submission, but an evidenced business-state change; missing data and high-risk Actions stop at human confirmation.

01 · NORMAL

正常任务Normal task

  • 输入订单、料件、位置、异常类型、照片、处理建议。Enter order, part, location, exception type, photo and recommendation.
  • 生成页面遵循既有字段、组件和 WMS 交互约定。The generated page follows existing fields, components and WMS interaction conventions.
  • 先在本地样例数据上复现流程。Reproduce the flow on local sample data first.

已知路径：需求→页面→本地验证。Known path: need → page → local validation.

02 · EXCEPTION

缺失信息与异常Missing data and errors

  • 缺订单、位置或异常类型：阻止提交并提示补齐。Missing order, location or type: block submission and request completion.
  • 无效状态、重复提交、接口超时：进入错误分支和重试/转人工。Invalid state, duplicate or timeout: use an error path and retry or hand off.
  • 具体必填规则、错误码和重试策略待 ISS 确认。Required rules, error codes and retry policy need ISS confirmation.
03 · CONTROL

人确认、回写与结果Human gate, write-back and result

  • 权限不足或证据不足：接管，不由生成结果替代决策。Insufficient access or evidence: hand off; generated output does not replace a decision.
  • 通过校验、权限、审核和接口测试后才回写状态。Write back only after validation, access, review and interface tests.
  • 记录原/新状态、操作者、时间、原因、附件和版本。Record old/new state, operator, time, reason, attachment and version.

最终结果（建议）：可追溯、一致、可回退；不是已实现收益。Final result (suggested): traceable, consistent and reversible; not a claimed realized benefit.
