可重复交付＋动手：用一张能力卡收口Repeatable Delivery + Hands-on: Close with One Capability Card

交付的最小单元不是“一个模型”，而是一套可验收、可接管、可维护、可停止的任务方法。The minimum delivery unit is not a model; it is a testable, operable, maintainable, stoppable task method.

可重复的方法流程Repeatable method

  1. 以真实任务而非资料数量立项；写角色、流程、更新责任、输入、输出和验收。
  2. 标注来源、有效期、审核人、用途和授权；先验证知识、检索、权限、规则和现有模型。
  3. 用结构化校验、工具验证、拒答/澄清/转人工降低幻觉；HR 保留人工决策。
  4. 比较质量、风险、成本、维护和可替换性，明确缩小、停止、转交、回滚。
  5. 固化变更链、评测、错误队列、知识更新、运营与责任交接，再考虑复用。
  1. Start from a real task, not document volume; define roles, workflow, owners, inputs, outputs, acceptance.
  2. Tag source, validity, reviewer, purpose, authorization; validate knowledge, retrieval, access, rules, existing models.
  3. Use structured checks, tools, and reject/clarify/takeover; retain human HR decisions.
  4. Compare quality, risk, cost, maintenance, replaceability; define narrow, stop, transfer, rollback.
  5. Codify change, evaluation, errors, updates, operations, and handoffs before reuse.

现场修改一个真实但可脱敏的规则或流程：

Modify one real but de-identifiable rule or workflow:

  • 补一条来源 / 有效期 / 审核人 / 用途记录，或新增“信息不足即转人工”规则。
  • 产出：小范围草稿、能力卡、验收字段、责任表。
  • Tom 主持确认：谁审核、谁实现、谁验收、谁运营、何时回滚。
  • 证据不足或风险过高：产出缩小 / 停止 / 转交卡，不强行产品化。
  • Add source / validity / reviewer / purpose, or a “missing information means hand off” rule.
  • Produce a narrow draft, capability card, acceptance fields, and responsibility table.
  • Tom confirms reviewer, implementer, acceptor, operator, and rollback point.
  • If evidence or risk is inadequate, produce a narrow/stop/transfer card; do not force productization.
